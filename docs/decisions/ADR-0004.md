# ADR-0004: RL 内核自研 PPO + GRPO, 不依赖 TRL

- 状态: Accepted (2026-10-08)
- 决策者: 主理人 晨星；架构师 楼构新
- 相关文档: `docs/OSS_STACK.md` 第 1.2 / 4.1 节, ADR-0001 (零依赖与注入的同一套纪律)
- 影响范围: 新增 `src/worldforge/rl/`, `pyproject.toml` (不新增依赖), `scripts/verify.py` (新增 RL 冒烟)

---

## 背景

| 事实 | 来源与时效 |
| --- | --- |
| TRL v1.13.0 (2026-09-09) 移除 `PPOTrainer`、`PPOConfig` 与 value-head 建模模块 (`AutoModelForCausalLMWithValueHead` 等) | 上游 PR #7020 "Remove PPOTrainer"; 检索日期 2026-10-07 |
| TRL 当前最新为 v1.14.0 | 同上 |
| TRL 官方主线已转向 GRPO 作为默认对齐路径; GRPO / DPO / KTO 等 Trainer 保留 | `docs/OSS_STACK.md` 第 1.2 节 |
| TRL 被本机判定为「仅参考」: 依赖 transformers / torch / peft / vLLM, 沙箱无 GPU 且安装成本极高 | `docs/OSS_STACK.md` 第 1.2 / 4.1 节 |
| 本机实测环境 | Python 3.13.14, 无 GPU, 无编译链, pip 只能 `--target` |

结论: 想要 PPO, 上游已经没有了; 想要 GRPO, 上游有但拉不动。同时本仓库的定位是「可插拔端到端 AI 平台」, RL 对齐能力是拼图的一块, 不能因为上游删了就缺。

---

## 决策

### D1 自研 RL 内核, 同时实现 PPO 与 GRPO

| 算法 | 自研内容 |
| --- | --- |
| PPO | clipped surrogate objective; GAE(lambda) 优势估计; 可插拔 value head; entropy bonus; 优势白化; 早停 (KL 目标或 clip fraction 阈值) |
| GRPO | 组内多次采样; 组内相对优势 `(r - mean(group)) / (std(group) + eps)`; 无 critic; 可选 KL 惩罚项 |
| 共用 | 轨迹缓冲 (rollout buffer)、mini-batch 采样、学习率调度、指标采集 |

### D2 纯 Python + stdlib, numpy 仅作可选加速

`src/worldforge/rl/` 默认路径零第三方依赖, 与 `core/` 同纪律。numpy 加速走 `core/accel.py` 同一套规则, 必须通过 parity 测试 `atol=1e-9`, 缺失时测试 skip。

### D3 提供 CPU 可跑的玩具环境做冒烟

| 环境 | 用途 |
| --- | --- |
| `MultiArmedBandit` | 验证 PPO 单步更新方向正确 (确定性最强) |
| `GridWorld` | 验证多步 credit assignment 与 GAE |
| `PreferenceBandit` | 验证 GRPO 的组内相对优势在无 critic 下也能收敛方向正确 |

冒烟判据是**方向性**的 (训练后平均回报上升、且随机种子固定下曲线可复现), 不是绝对值 -- 与 ADR-0002 的确定性纪律一致。

### D4 RL 组件走同一套 Port 抽象

| Port | 位置 | 说明 |
| --- | --- | --- |
| `Env` | `ports/rl_env.py` | `reset(seed) -> obs`, `step(action) -> (obs, reward, done, info)` |
| `Policy` | `ports/rl_policy.py` | `act(obs) -> action`, `logprob(obs, action) -> float`, `update(batch) -> dict` |
| `Trainer` | `ports/rl_trainer.py` | `train(env, policy, steps) -> TrainReport` |

策略后端可以是零依赖的线性/小 MLP, 也可以通过 ADR-0001 的 `LLM` Port 挂到真模型上 -- RL 模块不新增一套平行抽象。

### D5 TRL 禁止进入依赖树

| 允许 | 禁止 |
| --- | --- |
| 文档中把 TRL 写为算法设计与超参的对照参考 | `pyproject.toml` 中出现 `trl` |
| tests 里用 `pytest.importorskip("trl")` 做数值对照 (有则跑, 无则跳) | 默认路径 import TRL |
| 复现 TRL 论文公式时在注释里标注出处 | 复制 TRL 源码进仓库 (许可与维护双重风险) |

不 pin TRL 版本: 上游 v1.13 已删 PPO, pin 旧版本等于押注一条被放弃的线。

### D6 RL 模块不阻塞主线

`rl/` 属于 ADR-0001 优先级表的 P3 档。默认导入 `worldforge` 不触发 `rl/`; `verify.py` 的 RL 冒烟为独立 section, 独立于核心门禁。

---

## 理由

| 维度 | 说明 |
| --- | --- |
| 能力匹配度 | 上游已删除 PPOTrainer, 「依赖 TRL 拿 PPO」这条路客观上不存在; 自研是唯一可行解 |
| 成本 | 零货币成本; 工程成本约等于 1 个算法模块, 且不依赖 GPU 即可验证 |
| 延迟 | CPU 玩具环境下秒级完成, 不影响主链路 |
| 运维复杂度 | 低: 无新依赖、无新服务 |
| 风险 | 自研实现可能与主流实现对不齐 -> 用 TRL (装得上时) 与公开公式做数值对照测试 |
| 合规 | TRL 为 Apache-2.0, 本身合规; 否决它不是因为许可, 是因为依赖面与上游删除 |

一句话: 不是「不信任 TRL」, 而是「PPO 上游没了、GRPO 拉不动、本机跑不了」三个硬事实叠加后的唯一解。

## 后果

### 正面

| 项 | 说明 |
| --- | --- |
| 能力完整 | PPO 与 GRPO 都在, 不受上游删接口影响 |
| 可解释可审计 | 自研代码是公开仓库里最好的教学资产, 每一步梯度都能打断点 |
| 零依赖可跑 | 与 ADR-0001 铁律一致, `verify.py` 能证明 RL 内核真在训练 |
| 可插拔 | 策略后端能挂到 `LLM` Port, RL 与主链路复用同一套注入机制 |
| 无许可负担 | 不引入新的依赖许可面 |

### 负面

| 项 | 说明 | 缓解 |
| --- | --- | --- |
| 性能远低于 GPU 实现 | 纯 Python 无法做真实 LLM 的 RLHF | 明确定位: 内核正确性 + 小环境演示; 真实规模训练文档指向生产栈 |
| 无法复用 HF 生态 | 不能直接用 trl 的数据集、reward model、vLLM rollout | 提供 `Env`/`Policy` Port 让需要的人自己接 |
| 维护成本 | 两个算法的实现与测试要自己养 | 排在 P3, 不阻塞主线发布 |
| 与主流实现对不齐的风险 | 自研可能有细微公式差异 | 写对照测试: 手工构造 3 步轨迹, 手算期望梯度与实现比对; 装得上 TRL 时加 `importorskip` 对照 |
| 上游再次变化 | TRL 未来可能重新加回 PPO | 不影响: 我们不依赖它, 只把它当对照 |

## 替代方案

| 方案 | 内容 | 为何否决 |
| --- | --- | --- |
| A. pin `trl < 1.13` 继续使用 PPOTrainer | 锁旧版本 | 押注一条上游已明确放弃的线 (PR #7020 已删除); 且 trl 依赖 torch/transformers, 本机装不动, 与零依赖铁律冲突 |
| B. 只实现 GRPO, 放弃 PPO | 跟随上游主线 | 主理人裁决明确要求 PPO + GRPO 都要; 且 PPO 的 value head / GAE 是本仓库「可插拔」叙事里缺不掉的一块 |
| C. 依赖 stable-baselines3 | 成熟 RL 库 | 拉入 torch + gymnasium, 本机装不动; 且 SB3 面向连续控制, 与 LLM 对齐场景的 rollout 形态不匹配 |
| D. 不提供 RL 能力 | 只做 RAG + Agent | 与「世界级 AI 系统」的定位不符; RL 是 Agent 能力闭环 (工具调用策略优化) 的自然延伸 |
| E. 包装一层薄 adapter, 运行时才 import TRL | 有则调用, 无则自研 | 两套行为难以对齐, 违反 ADR-0001 的「默认实现必须真实现、行为可预测」; 且静默降级会掩盖数值差异 |
