# ADR-0005: License 红线 (AGPL-3.0 与 NVIDIA 专有许可禁止进入 extras)

- 状态: Accepted (2026-10-08)
- 决策者: 主理人 晨星；架构师 楼构新
- 相关文档: `docs/OSS_STACK.md` 第 3 节 (许可分布与三个红线), 仓库根 `LICENSE` (MIT, Copyright 2026 晨星)
- 影响范围: `pyproject.toml`, `Dockerfile`, `docker-compose.yml`, `.github/workflows/ci.yml`, `docs/`, `NOTICE`

---

## 背景

| 事实 | 说明 |
| --- | --- |
| 本仓库主许可 | MIT (`LICENSE`, Copyright 2026 晨星) |
| AGPL-3.0 组件 | MinIO (社区仓库已于 2026-04-25 归档, 2025-10-15 起停止发布社区镜像)、Garage |
| NVIDIA 专有组件 | TensorRT (10.x, 随 Triton 容器分发), 非开源、不可再分发 |
| AGPL 风险机理 | 网络交互即触发源码公开义务; vendor、静态/动态链接、随镜像分发都会把传染性带进来 |
| 专有许可风险机理 | 不可再分发, 出现在 `pyproject.toml` 或 CI 自动安装步骤即构成分发行为 |
| 仓库形态 | GitHub 公开发布 + 交付 Docker/compose 资产, 分发行为真实存在 |

一句话: 公开仓库 + 要发镜像, 许可不是「法务的事」, 是架构约束 -- 依赖树的形状由许可决定。

---

## 决策

### D1 extras 许可白名单

允许进入 `pyproject.toml` 任何 extras 的许可:

| SPDX ID | 代表项目 |
| --- | --- |
| `MIT` | FAISS, llama.cpp, ONNX Runtime, pytest, ruff |
| `Apache-2.0` | fastembed, Qdrant, transformers, vLLM, Ray, MLflow, JAX |
| `BSD-2-Clause` / `BSD-3-Clause` | NumPy, SciPy, scikit-learn, PyTorch |
| `PSF-2.0` | CPython 标准库 |
| `PostgreSQL` | pgvector |
| `ISC` / `0BSD` / `CC0-1.0` | 工具类小依赖 |

许可标识以各项目官方 `LICENSE` 文件与 SPDX 登记为准; 有疑义时以 CI 扫描结果为准, 不以文档表格为准。

### D2 许可黑名单 (红线)

| SPDX ID / 类别 | 涉及项目 | 处置 |
| --- | --- | --- |
| `AGPL-3.0` | MinIO, Garage | 禁止进入任何 extras、禁止 vendor、禁止链接、禁止随镜像分发; 仅可作为外部服务端点 |
| `SSPL` / `GPL-*` / `LGPL-*` | 同上类别 | 同 AGPL 处置 |
| `LicenseRef-NVIDIA-Proprietary` | TensorRT | 禁止进入 `pyproject.toml`; 禁止 CI 自动安装; 禁止打进镜像; 仅可出现在「用户自备 GPU 部署」文档章节 |
| 任何未登记专有许可 | 商业 SDK | 同上 |

### D3 对象存储: 抽象为 Port, 默认本地文件系统

| 规则 | 说明 |
| --- | --- |
| 抽象层 | `ObjectStoreProtocol` (`ports/objectstore.py`), 与 ADR-0001 的 10 个 Port 同一纪律 |
| 默认实现 | 本地文件系统 (零依赖、零许可风险) |
| MinIO / Garage / SeaweedFS | 一律作为**外部服务端点**: 通过 URL + 凭据在运行时连接, 仓库内不出现任何 AGPL 代码、不 import、不 vendor |
| compose 资产 | `docker-compose.yml` 中若出现对象存储, 只能用 Apache-2.0 的 SeaweedFS; MinIO / Garage 只能写在文档的「用户自行部署」章节 |

### D4 推理加速: 走 MIT / Apache-2.0 路线

| 用途 | 采用 | 禁止 |
| --- | --- | --- |
| CPU 推理 EP | ONNX Runtime (MIT), CPU EP | TensorRT EP 由用户本地自行配置后启用, 仓库不声明依赖 |
| Intel 硬件加速 | OpenVINO (Apache-2.0, 以官方 LICENSE 为准) | 任何 NVIDIA 专有 SDK |
| GPU 部署文档 | 文档中写「用户自备环境, 仓库不提供依赖声明」 | 在 extras 或 CI 中出现 `tensorrt` |

### D5 CI 合规门禁

| 门禁 | 工具 | 判定 |
| --- | --- | --- |
| 许可扫描 | `pip-licenses` 或 SPDX SBOM 生成 | 命中 `AGPL-*` / `GPL-*` / `SSPL-*` / `LicenseRef-*Proprietary` 即 fail |
| 依赖树快照 | `pip freeze > requirements.lock` | 每次 release 冻结, 配合 Dependabot 分组 PR |
| 源码引用扫描 | 简单 grep + 人工 review | 仓库源码中出现 AGPL 项目名作为 import 目标即 fail |
| Action SHA pin | 人工 + 脚本 | 禁止 `@v1` 浮动引用 |

### D6 Apache-2.0 NOTICE 义务

所有 Apache-2.0 依赖的版权与 NOTICE 原文必须汇总到构建产物根目录的 `NOTICE` 文件并随分发传递。CI 中校验 `NOTICE` 存在且覆盖当前依赖树。

### D7 灰名单与例外流程

| 类别 | 许可 | 处置 |
| --- | --- | --- |
| hypothesis | `MPL-2.0` (文件级弱 copyleft) | 仅 `[dev-strict]` 引用、不 vendor、不修改其源码, 可接受 |

任何例外 (必须引入黑名单组件) 需: (1) 在 `docs/decisions/LICENSE_EXCEPTION.md` 记录理由与替代方案评估; (2) 主理人书面批准; (3) CI 中显式标注豁免条目。

## 理由

| 维度 | 说明 |
| --- | --- |
| 能力匹配度 | 所有被禁组件都有 Apache-2.0 / MIT 等价替代 (SeaweedFS 替 MinIO、ONNX Runtime 替 TensorRT), 功能损失可忽略 |
| 成本 | 零成本; 不自建对象存储反而省运维 |
| 延迟 | 无影响 (外部服务端点的网络开销与任何 S3 实现相同) |
| 运维复杂度 | 略增: 对象存储需外部部署; 但本来 MinIO 也要独立部署 |
| 风险 | 否决风险极低; 放行风险是仓库被强制开源全部源码或面临侵权主张, 不可接受 |

关键判断: AGPL 与专有许可的风险是**不可逆**的 (一旦发现, 已发布版本无法撤回), 而规避成本只是一次架构抽象。风险与成本不对称, 所以设红线而不是设警告。

## 后果

### 正面

| 项 | 说明 |
| --- | --- |
| 合规可审计 | 白名单 + CI 扫描 + SPDX 标识, 外部贡献者一眼看懂 |
| 分发自由 | 可放心发 wheel / sdist / Docker 镜像, 无传染性顾虑 |
| 商业友好 | MIT 主许可 + 无 AGPL, 企业用户可直接使用 |
| 依赖可控 | 黑名单强制在选型阶段就排除, 不会埋到后期才发现 |
| 与主许可一致 | 与 `docs/OSS_STACK.md` 第 3 节的三个红线完全对齐 |

### 负面

| 项 | 说明 | 缓解 |
| --- | --- | --- |
| 放弃 MinIO | 社区最知名的自托管 S3 不能用 | MinIO 社区仓库已归档、停止安全修复, 本来就不该新项目押注; 文档推荐 SeaweedFS (Apache-2.0) |
| 放弃 TensorRT | GPU 推理性能天花板拿不到 | 本机无 GPU, 本来就用不上; 有 GPU 的用户自行在本地配置 ONNX Runtime 的 TensorRT EP |
| 对象存储需外部部署 | 默认实现是本地文件系统, 分布式场景要自己搭 | 抽象为 Port, 换实现只改环境变量 |
| 维护 NOTICE 有成本 | Apache-2.0 依赖多 | CI 自动生成与校验 |
| 门禁可能误杀 | 新引入的依赖许可未登记 | 例外流程 (D7) 提供明确通道 |

## 替代方案

| 方案 | 内容 | 为何否决 |
| --- | --- | --- |
| A. 允许 AGPL 组件进入 extras, 文档标注「可选」 | 用户自己选择是否安装 | extras 一旦声明就是分发通道; 用户装了 AGPL 依赖即可能触发义务, 而我们无法逐用户追踪; 「可选」不构成法律隔离 |
| B. 把 MinIO 打进 Docker 镜像, 声称「聚合体不传染」 | 依赖 AGPL 的 mere aggregation 抗辩 | 抗辩成本高、地域差异大, 且镜像分发是明确的再分发行为; 不值得为省一次抽象冒这个险 |
| C. 主许可改为 AGPL-3.0 以兼容 | 对齐最严许可 | 与「公开传播、企业可用」的目标冲突; MIT 是主理人已定 (`LICENSE` 已入库) |
| D. 依赖 TensorRT 但只在 CI 里装 | CI 不构成分发 | CI 日志与构建产物是公开的; 且这与 ADR-0001「CI 必须能跑零依赖门禁」相冲突, 会让 CI 依赖专有栈 |
| E. 不做许可扫描, 靠人工 review | 省工具链 | 60+ 个可选依赖 (见 `docs/OSS_STACK.md`), 人工必然漏; 且依赖是传递的, 人眼看不见间接依赖 |
