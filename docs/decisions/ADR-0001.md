# ADR-0001: 零依赖核心与 Protocol 注入架构

- 状态: Accepted (2026-10-08)
- 决策者: 主理人 晨星；架构师 楼构新
- 相关文档: `docs/ARCHITECTURE.md` 第 1/2/4/5/6 节, `docs/OSS_STACK.md` 第 0/2 节
- 影响范围: `src/worldforge/core`, `ports`, `adapters`, `pipeline.py`, `pyproject.toml`, `scripts/verify.py`

---

## 背景

| 约束 | 事实 |
| --- | --- |
| 运行环境 | Windows 11 沙箱, 无 GPU, 无 C/C++ 编译链 |
| 安装方式 | 只能 `pip install --target <dir>`, 大型 wheel 安装成本高且易失败 |
| 已装 | Python 3.13.14 / numpy 2.5.3 / pytest 9.1.1 |
| 发布形态 | GitHub 公开发布, 署名晨星, 主许可 MIT |
| 实测风险 | 已踩到的 12 个坑全部集中在算法层 (BM25 IDF 退化、摄入 upsert、证据渲染、秩相关未定义等), 算法层必须可单测、可替换 |
| 选型结论 | `docs/OSS_STACK.md` 已判定: 六层中只有数学基础层与代码工程层能在本机落地, 其余全部降级为可选 extras |

核心矛盾: 既要「clone 下来 `python scripts/verify.py` 就能跑」的极低门槛, 又要能接上 FAISS / Qdrant / 真 LLM 的生产能力。

---

## 决策

### D1 零依赖内核

`core/` 与 `ports/` 以及默认 adapters 只允许 import 标准库。裸 CPython 3.11+ 环境下 `python scripts/verify.py` 必须退出码 0。

### D2 能力抽象为 Protocol, 总数 10 个, 不裁剪

| # | Port | 文件 |
| --- | --- | --- |
| 1 | `LLM` | `ports/llm.py` |
| 2 | `Embedder` | `ports/embedder.py` |
| 3 | `VectorStore` | `ports/vectorstore.py` |
| 4 | `LexicalIndex` | `ports/lexical.py` |
| 5 | `Reranker` | `ports/reranker.py` |
| 6 | `DocStore` | `ports/docstore.py` |
| 7 | `Observer` | `ports/observer.py` |
| 8 | `Tool` | `ports/tool.py` |
| 9 | `Planner` | `ports/planner.py` |
| 10 | `Chunker` | `ports/chunker.py` |

主理人裁决: 保持 10 个, 不砍。`Chunker` 与 `LexicalIndex` 必须可替换 -- BM25 在小语料下 IDF 退化这个实测坑决定了稀疏索引不能只有一种实现, 分块策略则是检索质量的第一变量。

### D3 默认实现必须是真实现, 禁止 stub

判定标准写进测试, 不靠人工评审:

| 能力 | 禁止的 stub 形态 | 真实现最低验收标准 |
| --- | --- | --- |
| `Embedder` | 返回全 0 / 常量向量 | 不同文本产生不同向量; 相同文本逐位一致; 输出 L2 范数 == 1 |
| `VectorStore` | 恒返回 `[]` | 10 条已知向量检索 top1 正确, 余弦值等于定义值 (atol 1e-9) |
| `LexicalIndex` | 恒返回 0 分 | 构造 `n = N/2` 语料, 断言 IDF > 0 且 top1 正确 |
| `Reranker` | 原序返回 | 至少一个黄金 case 上 top1 发生变化且 MRR 不下降 |
| `LLM` | 返回固定字符串 | 输出句子必须来自证据原文; 换 query 输出必须变化 |
| `Chunker` | 整篇返回 1 块 | 长文档分块数 > 1, `ordinal` 从 0 连续 |
| `DocStore` | 写入后读不到 | `put_chunks` 后 `get_chunks` 全量命中且字段一致 |

CI 中加 `tests/test_adapters_default_impl.py`, 任一不满足即 fail。

### D4 生产实现走 extras + 环境变量, 缺失静默回退

| 能力 | 默认实现 | 环境变量 | 缺失时行为 |
| --- | --- | --- | --- |
| Embedder | `HashingEmbedder` (BLAKE2b 有符号散列) | `WORLDFORGE_EMBEDDER` | 回退 hashing |
| VectorStore | `InMemoryExactIndex` (精确余弦) | `WORLDFORGE_VECTORSTORE` | 回退 memory |
| LexicalIndex | `BM25Index` (自写 Robertson IDF) | `WORLDFORGE_LEXICAL` | 回退 bm25 |
| Reranker | `LexicalReranker` (IDF 加权词法) | `WORLDFORGE_RERANKER` | 回退 lexical |
| LLM | `ExtractiveMockLLM` (抽取式) | `WORLDFORGE_LLM` | 回退 mock |
| DocStore | `MemoryDocStore` | `WORLDFORGE_DOCSTORE` | 回退 memory |
| Observer | `MemoryObserver` | `WORLDFORGE_OBSERVER` | 回退 memory |
| Planner | `RuleBasedPlanner` | `WORLDFORGE_PLANNER` | 回退 rule |
| Chunker | `RecursiveCharChunker` | `WORLDFORGE_CHUNKER` | 回退 recursive |
| Tool 源 | builtin | `WORLDFORGE_TOOLS` | 回退 builtin |

回退规则: 工厂函数内部 `try: import ... except ImportError: raise BackendUnavailable`, `pick()` 捕获后 warn 一次, 回退默认实现, 并把 tag 写入 `degraded` 供 `/health` 暴露。`WORLDFORGE_STRICT=on` 时改为直接抛错, 用于生产环境防误配。

### D5 依赖方向单向, CI 静态校验

`serving -> pipeline -> agents/retrieval -> adapters -> ports -> core`。`core` 不得 import 任何上层, `ports` 不得 import `adapters`。`tests/test_layering.py` 用 AST 扫描强制。

### D6 环境变量前缀统一为 `WORLDFORGE_`

现状冲突: `docs/ARCHITECTURE.md` 用 `WF_*`, `docs/OSS_STACK.md` 用 `WORLDFORGE_BACKEND_*`, 主理人裁决用 `WORLDFORGE_DOCSTORE`。裁决如下:

| 形式 | 定位 |
| --- | --- |
| `WORLDFORGE_<CAPABILITY>` | **规范形式**, 文档与代码统一使用 |
| `WORLDFORGE_BACKEND_<CAPABILITY>` | 解析期兼容别名, 与规范形式等价 |
| `WF_<CAPABILITY>` | 解析期兼容短别名, 与规范形式等价 |

`config.py` 归一化后三者映射到同一个配置键; 出现两个别名同时设置且值不同 -> 抛 `ConfigError`。`docs/ARCHITECTURE.md` 第 5 节表格中的 `WF_` 前缀按本条理解为同一语义, 实现阶段不再维护三套写法。

### D7 交付门禁

`scripts/verify.py` 为一级门禁 (裸环境, 零 extras); `pytest` 为二级门禁 (可装全 extras)。CI 矩阵必须包含一个「不装任何 extras」的 job, 否则零依赖铁律无法被证明。

## 理由

| 维度 | 说明 |
| --- | --- |
| 能力匹配度 | Protocol + 注入正是「默认实现与生产实现共存」的原生表达方式, PEP 544 结构化子类型无需继承、无需注册 |
| 成本 | 默认栈零 API 调用, 边际成本 0 元; 生产栈成本按调用量计, 见 ADR-0003 与 `ARCHITECTURE.md` 第 14 节 |
| 延迟 | 无网络往返, 默认栈端到端预算见 `ARCHITECTURE.md` 第 14 节 |
| 运维复杂度 | 单进程、无服务依赖、无编译, clone 即跑 |
| 风险 | 主要风险是「默认实现质量不够被误当生产用」, 由 D3 的验收标准 + README 显式标注上限来兜 |
| 合规 | 零依赖路径天然无许可风险, 与 ADR-0005 一致 |

不选替代方案的理由见最后一节。

## 后果

### 正面

| 项 | 说明 |
| --- | --- |
| 可验证 | `verify.py` 在任何裸环境下都能证明系统真实可用, 不是纸面架构 |
| 可测试 | 算法层不依赖任何后端, 12 个实测坑全部可在纯单测里守护 |
| 可替换 | 换向量库 / 换嵌入 / 换 LLM 只改环境变量, 不动业务代码 |
| 可移植 | 不受沙箱编译链、GPU、网络限制影响 |
| 可传播 | 公开仓库的 star 与贡献门槛取决于「能不能立刻跑起来」 |

### 负面

| 项 | 说明 | 缓解 |
| --- | --- | --- |
| 功能上限低 | 散列嵌入无语义, mock LLM 不能生成新信息 | README 与 `/health.degraded` 显式标注; 生产场景必须开 extras |
| 两套实现漂移 | 默认实现与生产实现行为可能不一致 | 同一套黄金集在两种环境下各跑一遍, 见 ADR-0003 的两环境两列数字 |
| 性能天花板 | 纯 Python 暴力检索在十万级以上不可用 | numpy 加速路径必须通过 parity 测试 atol 1e-9 (`ARCHITECTURE.md` FM-17) |
| 维护成本 | 10 个 Port 的默认实现都要写真的 | 已按 P0-P4 排优先级, `ARCHITECTURE.md` 第 15 节 |
| 静默回退掩盖故障 | 用户以为在用 FAISS, 实际在跑暴力检索 | `degraded` 字段 + warn 一次 + `WORLDFORGE_STRICT=on` |

## 替代方案

| 方案 | 内容 | 为何否决 |
| --- | --- | --- |
| A. 直接依赖 numpy + faiss-cpu 作为硬依赖 | 不做零依赖内核 | 与沙箱约束冲突: 本机无法保证 wheel 可装; 且彻底失去「clone 即跑」的公开仓库传播力 |
| B. 只定义接口, 默认实现用 stub 抛 `NotImplementedError` | 装了 extras 才能用 | 默认路径无法跑通任何端到端链路, `verify.py` 失去意义, 12 个实测坑也无法离线守护 |
| C. 微服务拆分 (检索服务 / 推理服务 / 网关服务) | 各层独立进程 + RPC | MVP 阶段过度设计; 沙箱不能实跑 Docker; 分布式带来的非确定性与 ADR-0002 直接冲突 |
| D. 用 `abc.ABC` 取代 `typing.Protocol` | 强制继承 | 丢失结构化子类型, 单测 fake 必须继承基类, 第三方实现接入成本高 |
